The work flow for event selection is as follows.
Firstly the data (or Monte Carlo) collections are run over using an Athena job on the Grid.
This performs basic event reconstruction and is followed by the preselection stage.
We use release XX.XX to process the data.
The preselection software can be found in the package XX.
%The post-Athena processing code can be found in the ntuple subdirectory of the package.

In the Athena reconstruction, as a first step a JpsiFinder tool is run on muon or electron
containers, searching for di-lepton candidates with opposite sign and invariant mass
in the range [0, 6000] \mev. The \pt of the Leptons is required to be $> 2$ \gev.
%Di-lepton candidates are considered if the vertex $\chisqr$ per degree of freedom is
%$\chisqr < 30$.

\Bd candidates are then formed (by BCompositeParticleBuilder [??] tool) from two tracks associated
with leptons with $\pt > 500$~\mev and two other opposite-signed tracks not identified as muons
or electrons (i.e. hadrons from $K^*$ candidates). These four tracks are fitted into \Bd vertex
with track mass hypotheses set for \Bd and \Bdb (kaon mass assigned to positive or negative track).
Then secondary \Bd and \kstar vertices are fitted (using TrkVKalVrtFitter [???]), primary vertices
are refitted without the four candidate tracks and additional cuts are applied: 
%{\red Q) What type of fit is performed and are there any constraints used in the fit?}
\begin{itemize}
\setlength{\itemsep}{0pt}%
\setlength{\parskip}{0pt}%
 \item \Bd or \Bdb vertex $\chisqr < 205$, [??]
 \item \Bd or \Bdb mass in the range [3000, 6000] \mev, [??]
 \item \kstar or \akstar mass in the range [600, 1050] \mev. [??]
\end{itemize}

Events are saved in a linked per-event tree with one \kstar (\akstar) candidate for each \Bd (\Bdb) candidate.
Both possible $K^\pm\pi^\pm$ assignments are considered given a set of four final state tracks, i.e. for each
4-particle sets we normally can build both a \kstar and \akstar, hence this lead to two $B$ candidates, a \Bd
and a \Bdb. Each of the two candidates needs to pass the specific mass cuts.
In addition to two candidates per 4-particle sets, multiple sets of four final state particles can be formed.
Both these cases result in multiple candidates per event.

For the reconstruction of primary vertex (PV), the PV of the $B$ candidate is chosen to be
the one closest to the reconstructed decay vertex of the \Bd or \Bdb candidate using the three-dimensional
distance.

After the Athena reconstruction described above, a preselection is applied as follows:
\begin{itemize}
\setlength{\itemsep}{0pt}%
\setlength{\parskip}{0pt}%
 \item opposite charged lepton pairs and hadron pairs
 \item $\Delta R_{\ell\ell} \geq 0.1$
 \item {\color{blue}\pt(e)$\geq 5$~\gev }/{\color{red} \pt($\mu$)$\geq 6$~\gev}
 \item $|\eta|(\ell)\leq 2.5$
 \item \pt(hadrons)$\geq 0.5$~\gev
 \item $|\eta|$(hadrons)$\leq 2.5$
 \item $m(\ell\ell)\leq 7$~\gev
 \item {\color{blue}$m(K\pi ee) \in [3000,6500]$~\mev} / {\color{red}$m(K\pi \mu\mu) \in [4700,6000]$~\mev}
 \item {\color{blue}$m(K\pi) \in [690, 1110]$~\mev} / {\color{red}$m(K\pi) \in [800, 1000]$~\mev}
 \item Track Quality requirements (Loose) on all four tracks
 \item {\color{blue}ID requirements on electrons (LooseElectron)}
 \item {\color{red}ID requirements on muons (???)}
% \item $|m(K\pi)-m(K^{0*})|\leq 50$~\mev
%\item \Bd$(\chisqr) \leq 2$
%\item $\tau$(\Bd)$\geq 0.2$~ps
\end{itemize}

The cut flows from this preselection for signal events ($\Bd \to \kstar ee$) and resonance events
($\Bd \to J/\psi(ee)\kstar$) are shown in Tables~\ref{tab:presel:sigele} and~\ref{tab:presel:resele}
for the electron final state and in Tables~\ref{tab:presel:sigmu} and~\ref{tab:presel:resmu}
for the muon final state.
These tables show the number of candidates and events passing each stage of the preselection
and also the best-candidate selection for the MC samples.
The truth-matched number of candidates/events are obtained by using truth-level information
and a single candidate is matched to the truth candidate generated.
%A truth-matched event is defined as one in which at least one candidate is truth-matched.
The (truth-matched) relative efficiencies are then given, showing the fraction of (truth-matched)
events that survive a given cut. Purity is defined as the fraction of events that have a%t least one
truth-matched candidate at any given cut. Finally, the ratio of the relative efficiency
to the truth-matched relative efficiency is also given, where a value above one indicates
that a cut increases the signal purity and vice-versa.
